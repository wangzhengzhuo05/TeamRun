# TeamRun PRD v0.1

## 1. 产品定位

**TeamRun 是面向软件研发团队的 Human-Agent 协作平台。**

它基于 TeamRun 的多 Agent 工作空间能力，新增 Team Space，让团队成员可以把任务和上下文直接交给多个 Agent 执行，并统一管理执行过程和结果。

核心理念：

&gt; **一个人管理多个 Agent，一个团队管理人和 Agent。**

核心链路：

```text

Team Task

   ↓

Context

   ↓

Personal Workspace

   ↓

Multi-Agent Execution

   ↓

Human Review

   ↓

PR / Result

   ↓

Team

```

---

## 2. 目标用户

第一阶段只服务：

**5～50 人的软件研发团队，尤其是已经大量使用 Codex、Claude Code、OpenCode 等 Coding Agent 的团队。**

核心问题：

- 开发者同时运行多个 Agent，难以统一管理

- Task、讨论、文档与 Agent 之间上下文割裂

- Agent 执行过程对团队不可见

- Agent 结果需要人工整理后再同步到团队

- 管理者无法清楚了解“人 + Agent”整体工作状态

---

## 3. 核心产品结构

TeamRun 包含三个核心模块。

### Team Space

负责团队协作：

- Project

- Task

- Channel

- Team Agent

- Team Members

### Personal Workspace

基于 TeamRun 实现个人执行：

- 多 Task

- 多 Agent

- Terminal

- Git Worktree

- Diff

- Test

- Agent Status

### Context Bridge

连接 Team 和 Workspace：

```text

Task + Discussion + Docs

          ↓

   Context Snapshot

          ↓

        Agent

          ↓

 Diff / Test / PR / Summary

          ↓

      Team Task

```

这是 TeamRun 最核心的差异化能力。

---

## 4. MVP 核心功能

### P0：Task

Task 是系统核心对象。

每个 Task 关联：

```text

Task

├─ Owner

├─ Context

├─ Repository

├─ Agent Runs

├─ Worktrees

└─ Results

```

### P0：Multi-Agent Workspace

一个用户可以：

```text

TASK-101

├─ Codex

├─ Claude

└─ OpenCode

```

每个 Agent 使用独立 Worktree，并统一显示：

- Working

- Needs Input

- Review

- Completed

- Failed

### P0：Context Bridge

点击 **Open in TeamRun** 后，自动把 Task 相关信息整理成 Context Snapshot 并提供给 Agent。

### P0：Result

Agent 完成任务后，统一产生：

- Diff

- Test Result

- Commit

- PR

- Summary

由用户 Review 后 Publish 到 Team Space。

### P1：Team Space

实现基础：

- Organization

- Project

- Task

- Channel

- Team Agent

第一阶段不做完整 Docs、Email、CRM、Calls 等功能。

---

## 5. 核心用户流程

TeamRun v1 只需要把这一条流程做到足够好：

```text

创建 / 导入 Task

        ↓

获取团队上下文

        ↓

Open in TeamRun

        ↓

启动一个或多个 Agent

        ↓

独立 Worktree 并行执行

        ↓

查看 Agent 状态

        ↓

Diff / Test / Compare

        ↓

Human Review

        ↓

PR / Publish

        ↓

自动更新 Team Task

```

---

## 6. 产品原则

### Human in Control

Agent 负责执行，人负责目标、审核和最终决策。

### Agent Neutral

不绑定某一家 Agent。

优先支持：

- Codex

- Claude Code

- OpenCode

- Generic CLI Agent

### Private by Default

个人 Workspace 中的失败尝试、临时代码和日志默认不共享。

只有经过 **Publish** 的结果才进入团队上下文。

---

## 7. 第一阶段不做

为了控制范围，MVP 暂不做：

- Slack 替代

- Notion 替代

- Linear 替代

- GitHub 替代

- 自研 Coding Agent

- Email / CRM / Calls

- 复杂 Agent-to-Agent 自主协作

- 通用办公场景

第一阶段只聚焦：

&gt; **软件研发团队的 Human-Agent 工作流。**

---

## 8. 产品阶段

### Phase 1 — Workspace

基于 TeamRun 完成多 Task、多 Agent、Worktree、Diff、Test、Review。

### Phase 2 — Context Bridge

完成：

```text

Team Task

→ Context

→ Agent

→ Result

→ Team

```

形成第一个完整 MVP。

### Phase 3 — Team

加入 Team Space、Team Agent、权限和共享上下文。

### Phase 4 — Management

加入 Agent Cost、Team Dashboard、Agent Analytics 和 Work Graph。

---

## 9. 一句话定义

&gt; **TeamRun 是一个让软件团队统一管理人和多个 Agent 如何共同完成任务的协作平台。**

产品核心：

&gt; **One team. Many agents. Run together.**
